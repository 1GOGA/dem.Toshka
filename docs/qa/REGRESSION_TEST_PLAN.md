# План регрессионного тестирования и обеспечения качества dem.Toshka

**Дата утверждения:** 19 ноября 2026 г.  
**Ветка:** `feature/product-takeover-overhaul`  
**Статус:** Утверждённый план тестирования (QA Matrix & Regression Protocol)  
**Инструменты:** `pytest` (бэкенд), `vitest` / TypeScript compiler (фронтенд)

---

## 1. Методология и принципы контроля качества

1. **Никаких вымышленных тестов:** Тест считается пройденным только в том случае, если команда была фактически запущена в окружении, вернула код завершения 0, и вывод проверен.
2. **Тестирование на реальных данных CS2:** Тестовый набор опирается на настоящие демки CS2 (включая официальные матчи FACEIT на картах `de_nuke`, `de_anubis` со 128-тикрейтом и матчи соревновательного режима Valve с 64-тикрейтом).
3. **Защита от регрессий:** Любое исправление бага сопровождается добавлением юнит-теста, предотвращающего повторное появление дефекта в будущих релизах.

## 3. Детальные сценарии тестирования

### 3.1 Тесты парсера демок (Parser Tests)
- [x] **TC-P01:** Корректный разбор заголовка демки CS2 (карта, тикрейт, длительность в секундах).
- [x] **TC-P02:** Извлечение всех раундов с четкими границами `start_tick`, `end_tick`, `official_end_tick`.
- [x] **TC-P03:** Идентификация суицидов (урон от падения `weapon='world'`) — флаг `is_suicide=True`, исключение из фрагов.
- [x] **TC-P04:** Идентификация тимкиллов (убийство союзника) — флаг `is_teamkill=True`, исключение из фрагов.
- [x] **TC-P05:** Идентификация взрыва бомбы (`planted_c4`) — смерть не приписывается игроку как суицид или тимкилл.
- [x] **TC-P06:** Обработка поврежденных и неполных .dem файлов с безопасной генерацией ошибки без падения бэкенда.

### 3.2 Тесты статистики и аналитики (Statistics Tests)
- [x] **TC-S01:** Математическая проверка формулы K/D = `kills / max(1, deaths)`.
- [x] **TC-S02:** Проверка процента хедшотов: `headshot_pct = (headshots / kills) * 100`, при 0 убийств равен `0.0`.
- [x] **TC-S03:** Расчет KAST % — доля раундов с хотя бы одним убийством, ассистом, выживанием или разменом.
- [x] **TC-S04:** Проверка первых дуэлей раунда: ровно одно первое убийство и одна первая смерть на каждый состоявшийся раунд.
- [x] **TC-S05:** Проверка окна размена: убийство обидчика тиммейта в течение 4 секунд засчитывается как Trade Kill.

### 3.3 Тесты детектора хайлайтов (Highlight Tests)
- [x] **TC-H01:** Детекция серий 2K, 3K, 4K и ACE в рамках допустимого временного окна.
- [x] **TC-H02:** Проверка динамических границ клипа: `clip_start_tick >= round.start_tick` и `clip_end_tick <= round.official_end_tick`.
- [x] **TC-H03:** Проверка скоринга: ACE гарантированно получает более высокий балл, чем 3K при прочих равных условиях.
- [x] **TC-H04:** Объяснимость скоринга: объект `score_breakdown` содержит расшифровку каждого начисленного балла.

### 3.4 Тесты базы данных и кэша (Storage Tests)
- [x] **TC-D01:** Повторное сканирование уже обработанной демки не создает дубликатов в базе (`fingerprint` уникален).
- [x] **TC-D02:** Удаление записи демки каскадно удаляет всех связанных игроков, раунды, события смертей и хайлайты.
- [x] **TC-D03:** Корректная работа индексов по `steam_id` и `demo_id` для мгновенных выборок.

### 3.5 Тесты контракта со студией (Cinematic Studio Bridge Tests)
- [x] **TC-B01:** Генерация `StudioJobManifest` v1.0 формирует валидный JSON, соответствующий схеме.
- [x] **TC-B02:** Манифест содержит абсолютный путь к демке, диапазон тиков, SteamID главного героя и список событий.
- [x] **TC-B03:** Корректный парсинг отчета `StudioJobStatus` при успешном завершении или ошибке в студии.

## 4. Регламент запуска тестов

```powershell
# 1. Запуск полного набора юнит- и интеграционных тестов Python:
.venv\Scripts\pytest -v

# 2. Быстрый прогон регрессионного набора:
.venv\Scripts\pytest -q

# 3. Проверка типов и сборка фронтенда:
npm.cmd --prefix frontend run build
```
