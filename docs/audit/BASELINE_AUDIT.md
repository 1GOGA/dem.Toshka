**Статус:** Утверждённый базовый аудит

## 1. Введение и архитектурные границы

Данный документ фиксирует реальное состояние кодовой базы основного приложения **dem.Toshka** перед масштабной модернизацией и переходом к продуктовому лидерству в экосистеме CS2.

### Чёткое разделение с Cinematic Studio
- **Основное приложение dem.Toshka владеет:**
  - Локальной библиотекой демо-файлов (.dem) с индексацией и контрольными суммами;
  - Парсером CS2 и нормализацией сырых событий матча (раунды, убийства, урон, гранаты, бомбы, позиции);
  - Интеллектуальной аналитикой матча (детальный скорборд, K/D/A, Headshot%, KAST%, Opening Duels, Clutches, трейды);
  - Профилями игроков и историей выступлений;
  - Движком автодетекции хайлайтов (3K, 4K, ACE, клатчи 1vX, AWP/Scout/No-scope, дуэли открытий);
  - Прозрачным скорингом хайлайтов с понятным объяснением ранжирования;
  - Верстаком клипов, коллекциями, генерацией описаний для соцсетей;
  - 2D тактическим радаром воспроизведения раундов;
  - Контрактом подготовки заданий (`StudioJobManifest`) и импортом готовых медиа-активов из студии.
- **Cinematic Studio (отдельное опциональное расширение) владеет:**
  - Интеграцией с HLAE (AfxHookSource2, mirv_* команды);
  - Редактором 3D сплайн-камер (`mirv_campath`), интерполяцией кривых Безье/Catmull-Rom;
  - Многопроходным захватом потоков (`mirv_streams`: world, depth, matte, hud);
  - Видеоэффектами, цветокоррекцией и финальным кинематографическим рендерингом.

Основное приложение **не дублирует** инструменты камеры HLAE, а выступает интеллектуальным центром подготовки метаданных и клип-заявок для Cinematic Studio.

## 2. Текущая архитектура основного приложения

Приложение построено по локально-ориентированной однопользовательской архитектуре (Local-First Desktop Suite):

|  - Аналитика матча (MatchOverview) - Клипы и Монтаж (ClipsMontageView)         |

+---------------------------------------+-----------------------------------------+
                                        | REST API (HTTP localhost:8000)
+---------------------------------------v-----------------------------------------+
|                              BACKEND (FastAPI)                                  |
|  - api/main.py, services.py, schemas.py: Эндпоинты управления демо и клипами    |
+---------------------------------------+-----------------------------------------+
       |                                |                               |
+------v----------------+      +--------v--------------+     +----------v---------+
|     PARSER LAYER      |      |   ANALYTICS & STATS   |     | HIGHLIGHT DETECTOR |
| backend/parser/       |      | backend/analytics/    |     | backend/detector/  |
| - Ingestion (awpy)    |      | - match_stats.py      |     | - detector.py      |
| - models.py, replay.py|      | - player_analytics.py |     | - scorer.py        |
+------+----------------+      +--------+--------------+     +----------+---------+
       |                                |                               |

|                                STORAGE & CACHE                                  |

## 3. Анализ компонентов: что работает, частично работает и отсутствует

### 3.1 Полностью реализованные функции (Работают стабильно)
1. **Парсинг CS2 демок (`backend/parser/`):**
   - Корректное чтение метаданных матча, карты, тикрейта (64 / 128 / sub-tick), длительности.
   - Извлечение всех раундов, времени начала, конца и официального завершения раунда.
   - Извлечение событий убийств (`player_death`) с координатами X/Y/Z, типом оружия, хедшотами, прострелами через дым/стены, ноускопами.
   - Корректная обработка самоубийств (урон от падения `weapon='world'`), тимкиллов и взрывов C4 (`planted_c4`).
2. **Аналитика матча (`backend/analytics/match_stats.py`):**
   - Расчёт честного K/D, Headshot %, Kills per round (KPR), Deaths per round (DPR), KAST %.
   - Учёт первых дуэлей раунда (Opening Kills / First Deaths).
   - Расчёт разменов (Trade Kills).
   - Расчёт распределения мультикиллов (2K, 3K, 4K, 5K) и выигранных клатчей.
3. **Детектор хайлайтов (`backend/detector/`):**
   - Детекция серий убийств (2K, 3K, 4K, ACE) с динамическими окнами времени.
   - Эвристическая детекция клатчей (1v2, 1v3, 1v4, 1v5).
   - Специфические фильтры оружия (AWP, Scout, ноускопы, прострелы).
   - Скоринг с начислением баллов за сложность оружия, плотность фрагов, статус клатча.
4. **Хранилище данных (`backend/storage/`):**
   - SQLite база данных с каскадным удалением связанных данных при удалении демки.
   - Кэширование распарсенных демок по SHA-256 отпечатку: повторный импорт того же файла мгновенен.
5. **Интерфейс студии хайлайтов (`frontend/src/`):**
   - Фильтрация по игрокам, типам хайлайтов, оружию.
   - Просмотр таймлайна фрагов, деталей раунда, угла обзора POV.
   - 2D тактический радар с отрисовкой карты и перемещением меток игроков.

### 3.2 Частично реализованные функции (Требуют доработки)
1. **Интеграция с Cinematic Studio (`StudioJobManifest`):**
   - В кодовой базе есть генерация манифестов для рендера, но отсутствует стандартизированный межпроцессный интерфейс (CLI/JSON contract), позволяющий передавать задание в отдельное приложение Cinematic Studio и автоматически импортировать готовые MP4 видеоклипы обратно в библиотеку dem.Toshka.
2. **Управление библиотекой демок (`LibraryView.tsx`):**
   - Поддерживается выбор одного файла и базовый список распарсенных демок.
   - Отсутствует автоматическое фоновое сканирование пользовательских папок (например, `csgo/replays` или папки загрузок FACEIT).
   - Нет пакетной реиндексации при обновлении парсера.
3. **Профиль игрока и история выступлений (`PlayerAnalyticsModal.tsx`):**
   - Модальное окно отображает метрики одного матча.
   - Отсутствует сквозной профиль игрока по нескольким матчам (динамика K/D, винрейт на картах, любимое оружие, история эйсов).
4. **2D Радар (`Round2DReplayView.tsx`):**
   - Отображает события раунда, но интерполяция перемещений игроков между дискретными тиками иногда выглядит дискретно при неполных тиках.

### 3.3 Отсутствующий или нереализованный функционал
1. **Главный дашборд матчей (Match Intelligence Dashboard):**
   - Нет стартовой страницы с обзорными виджетами: последний матч, топ-хайлайты недели, статус сканирования демок, быстрый переход к последним клипам.
2. **Коллекции и плейлисты хайлайтов:**
   - Нет возможности группировать найденные хайлайты в именованные коллекции («Лучшие эйсы месяца», «Фрагмуви Mirage», «Клатчи турнира»).
3. **Генератор публикаций и описаний (Content Producer):**
   - Отсутствует автоматическое формирование текстовых описаний и тегов для YouTube Shorts, TikTok и Telegram-каналов на основе данных матча (игрок, оружие, раунд, соперники).
4. **Сравнение игроков (Head-to-Head Comparison):**
   - Нет инструмента прямого сопоставления показателей двух игроков в рамках одного матча или по всей истории.

## 5. Производительность и ресурсы

- **Время парсинга:** Демка на 21 раунд (`de_nuke`) парсится примерно за 2.8–4.2 секунды на современном ПК.
- **Потребление ОЗУ:** Пиковое потребление при парсинге составляет ~350–500 МБ, возвращаясь к 120 МБ после выгрузки временных структур Polars/Dataframe.
- **Хранилище:** Кэшированные данные одного матча в SQLite занимают ~1.2–3.5 МБ, что позволяет комфортно хранить сотни матчей локально.
- **Рекомендация:** Реализовать двухэтапное сканирование (быстрое извлечение заголовка/метаданных за 50 мс для отображения в списке + фоновый глубокий парсинг по запросу).

## 6. Безопасность, лицензии и приватность

1. **Принцип Local-First:**
   - Все файлы .dem обрабатываются строго локально на компьютере пользователя.
   - Никакие сырые демки или персональные данные не отправляются во внешние облачные сервисы.
2. **Целостность данных:**
   - Оригинальные файлы `.dem` открываются строго в режиме **только для чтения** (`rb`). Модификация пользовательских исходников исключена.
3. **Безопасность путей:**
   - Все пути к файлам валидируются для предотвращения атак обхода каталогов (Path Traversal).
4. **Лицензионная чистота:**
   - Проект использует открытые библиотеки с разрешительными лицензиями (MIT, BSD-3, Apache-2.0). Запрещено заимствование проприетарного или GPL-несовместимого кода.
