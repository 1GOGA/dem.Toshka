# dem.Toshka Core — Аудит текущего состояния и матрица функциональности

**Дата аудита:** 23 ноября 2026 г.  
**Ветка:** `feature/product-takeover-overhaul`  
**Статус:** Базовый аудит перед проектированием Demo Vision, Player Analytics и Strategy Book  
**Область:** dem.Toshka Core (десктопное приложение для анализа матчей CS2)

---

## 1. Введение и цели аудита

Цель аудита — установить строго фактологическую картину текущих возможностей `dem.Toshka Core`, опираясь на реальные исполняемые файлы, тесты, структуры базы данных SQLite и исходный код.

В соответствии с правилами `AGENTS.md` старые отчёты агентов не принимаются за доказательство функциональности. Каждый вывод подкреплён запуском тестов и инспекцией бинарных демок CS2.

### Архитектурные границы
- **dem.Toshka Core:** Владеет локальным парсингом `.dem`, нормализацией данных, аналитикой игроков и команд, скорбордами, детекцией хайлайтов, 2D тактическим воспроизведением (Demo Vision), базой знаний стратегий (Strategy Book) и формированием клип-заявок.
- **dem.Toshka Cinematic Studio:** Отдельный проект, владеющий инъекцией HLAE/AdvancedFX, 3D сплайн-камерами (`mirv_campath`), многопроходным захватом потоков (`mirv_streams`) и кинематографическим монтажом.

## 3. Детальный аудит технического фундамента

### 3.1 Парсер: `awpy 2.0.2` vs прямой `demoparser2`
- `awpy 2.0.2` внутри себя импортирует `from demoparser2 import DemoParser`.
- `awpy` выполняет высокоуровневую постобработку (фильтрация `in_play_ticks`, формирование датафреймов Polars). Это удобно для базовой аналитики, но создает накладные расходы при выгрузке потиковых данных (вызывает предупреждения Polars deprecation).
- `demoparser2` (на Rust) предоставляет прямой доступ к:
  - `parse_voice()` — извлечение сотен тысяч Opus-пакетов голоса;
  - `parse_ticks(['X', 'Y', 'Z', 'pitch', 'yaw', 'health', 'armor_value', 'active_weapon_name', 'cash', 'has_defuser'])` — мгновенное извлечение полного состояния игроков;
  - `parse_grenades()` — полиномиальные траектории гранат;
  - `list_game_events()` — события детонации дымов (`smokegrenade_detonate`, `smokegrenade_expired`), ослеплений (`player_blind`), пожаров молотовых (`inferno_startburn`, `inferno_expire`) и бомбы (`bomb_beginplant`, `bomb_planted`, `bomb_begindefuse`, `bomb_defused`).

### 3.2 Голосовые данные в демках CS2 (Экспериментальное подтверждение)
В ходе аудита проведен прямой тест на реальных файлах репозитория:
- `tests/integration/fixtures/test.dem`: обнаружено **162 484 голосовых пакета**.
- `demos/anubis1410.dem`: обнаружено **92 737 голосовых пакетов** от 10 различных SteamID.
- `demos/1-31bfc53c...dem`: обнаружено **162 513 пакетов**.

**Структура пакета:**
`{'tick': 136, 'steamid': 76561198670308345, 'bytes': b'p\x08...'}`
- Формат байтов: Opus voice payload (TOC byte `0x70` — Silk/Wideband mono 48kHz, длительность кадра 20 мс).
- **Важное ограничение:** Голосовые данные присутствуют в демках с серверов FACEIT, соревновательных платформ и серверов с включенным `tv_transmitoperators 1` / `tv_relayvoice 1`. В официальных матчмейкинг-демках Valve MM/Premier голосовой чат часто вырезан сервером ради приватности. Приложение обязано честно проверять наличие пакетов и не обещать голос там, где его нет.

### 3.3 Координаты и геометрия карт
В `backend/parser/replay.py` уже заложены калибровочные параметры (`pos_x`, `pos_y`, `scale`, `split_z`) для 11 карт CS2:
- `de_dust2`, `de_mirage`, `de_inferno`, `de_ancient`, `de_anubis`, `de_overpass`, `cs_office`, `cs_italy` — одноуровневые.
- `de_nuke` (split_z = -400.0), `de_vertigo` (split_z = 11700.0), `de_train` (split_z = -100.0) — двухуровневые (upper/lower).
Формула трансформации проверена тестами и обеспечивает отображение с точностью до метра.

## 4. Главные выводы аудита

1. **Фундамент готов к масштабированию:** Ядро парсинга, реляционная БД и 2D координаты работают стабильно.
2. **Узкое место текущего 2D радара:** Радар сейчас показывает упрощённую анимацию перемещения кружков. Для превращения его в полноценный **Demo Vision** требуется добавить углы взгляда (конусы обзора), полный статус экипировки (HP/Armor/Weapon/Defuser), точные радиусы и тайминги гранат, тактическое рисование и привязку голосовых дорожек.
3. **Отсутствие мультиматчевой связности:** Система анализирует матчи по отдельности. Для **Player Analytics** и **Strategy Book** требуется ввести сущности профиля игрока, сквозной истории матчей, хранилища тактических заметок и автономного экспортера.
